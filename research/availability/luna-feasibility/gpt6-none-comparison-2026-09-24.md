# GPT-6 Luna none の同一入力比較（2026-09-24）

## 結論

`gpt-5.6-luna` / `reasoning.effort: none` から `gpt-6-luna` / `none` への**モデル名だけの置換は見送る**。保存済みの同一入力・同一参照判定で、現行AI採用8施設のうち採用基準を維持したのは2施設だけだった。5/36 API応答は `completed` でも複数の `output_text` を含み、現行の `readWithLuna` は連結後のJSON解析に失敗する。最後の有効なJSONだけを仮に採る場合も、採用基準を維持したのは3/8施設だった。保留中の4施設は、いずれも新たに基準を通過しなかった。

費用は、36件の実測usageとそれぞれの公式料金で、5.6 Luna **$0.251386**、6 Luna **$0.146015**（41.9%減）の推計。請求書の確定額ではない。モデル6の出力トークンは180,389から257,111へ42.5%増えたため、単価差ほど総額は下がらなかった。[5.6料金](https://developers.openai.com/api/docs/models/gpt-5.6-luna)、[6料金](https://developers.openai.com/api/docs/models/gpt-6-luna)。

## 方法

- 過去に採用したAI 8施設と、典型的な誤読で保留した4施設を選んだ。対象は合計12施設・439施設日。各施設3回、計36回。APIキーはユーザー指定の `~/.zshrc` から実行プロセス内で読み、表示・保存していない。
- 2026-09-20〜22の保存済み公式資料を用いた既存リクエストで、**`model` だけ** `gpt-6-luna` に変更した。`instructions`、画像の `detail: high`、schema、対象日、`max_output_tokens`、`store: false` は固定した。5.6の保存応答36件が元のリクエストhashと一致することを確認した。6の36件はすべて `completed`、指定モデル・`none`、reasoning token 0、変更後リクエストhash一致。
- 既存の `score_candidate_runs.py` の `score_facility` と、人が原資料を照合した既存の参照判定を使った。参照判定は現地の真の正解ではなく、一部に解釈上の曖昧さがある。過去の資料・対象日に対する比較であり、現在の公式予定や将来の正答率は検証していない。
- 「現行コード」は複数 `output_text` をそのまま連結し、解析不能ならその施設の全日を `unknown` とする。一方「最終JSON」は最後の有効なテキスト部分だけを仮に採った読解比較で、未実装の救済方式である。後者でも公開可能と判断したわけではない。
