## 結論

step1（未対応候補の確認）・step2（資料と評価条件の固定）・step3（独立比較）は完了。step4は非公開の有限試験収集を実装し、不合格結果が流れないことを実資料の再取得で確認した。合格施設がないため、正しい利用可能日を増やす実運用試験までは進めていない。公開サイト・availabilityデータ・定期ジョブへの接続やデプロイは行っていない。

## Astraの訂正と評価の限界

主担当による原画像の再確認で、Astraの知多10/10（実際は9–17時可）と10/15（実際は全時間不可）の2件の行読み違いを確認した。Lunaはこれらの時間/可否を正しく読めた。Astraの生回答は変更せず、`primary-adjudications.json` に修正前後と根拠を保存し、`primary-reviewed-reference.json` を比較用に生成した。ユーザーのannotation表は変更していない。

したがって、比較表の一致数は人手goldに対する精度ではない。Astraも常に正解ではなく、Luna3回の一致も正しさの保証にはならない。条件・引用の全文品質もcore一致数だけでは測れない。

## 非公開の試験収集

`shadow_collect.py` は、レビュー済み記録と原資料URL/hashを指定する有限キャッシュの検証器。新しい日をAI推論するcollectorではない。外部APIキー不要で、公式資料をHTTPS再取得して一致を確認する。変更・取得失敗・未承認・未検証の日付は利用時間を消してunknownに戻す。出力は研究用 `local-state/shadow/` に限定し、同一run-idの上書きを拒否する。

今回のapprovalは5施設すべて `approved: false`。合格扱いの例を作るためにAstraの正解をLuna出力へ代入することはしていない。

- 基準: daily liveの隔離workspaceで取得した5施設×31日=155件は全件unknown。古いcheckoutの14日分snapshotを基準にはしなかった。
- 実行A/B: 同一日中の2回。各回10URLを新たに取得し、全hash一致。Balcomの共通資料は各回1回だけ取得。
- 両回とも既知日0、利用可能日0、unknown155。未承認出力が混入しないことを確認。
- これは複数日にわたる運用試験や新しい月の未知資料での成功実績ではない。

## 費用・検証・レビュー

Luna15回のusageに基づく推計費用は **$0.10801348**。取得時の[公式Luna料金](https://developers.openai.com/api/docs/models/gpt-5.6-luna)（input $0.20/M、cache hit $0.02/M、cache write $0.25/M、output $1.20/M）で算出。請求書上の確定額ではない。AstraはCodex側の利用枠で実行した。

- Python研究テスト11件: PASS（保存/競合、未承認、資料変更、取得失敗、未検証日、時刻整合など）。
- `npm run test:daily:fixtures`: PASS。
- `npm run test:daily`: PASS（実資料収集・build・desktop/mobile smoke、checkout data/distを変更しない隔離実行）。
- 公開アプリの変更がないため、通常build/test/lint/smokeをさらに個別実行してはいない。daily内のbuild/smokeは実施済み。
- 棚卸しとshadow実装/テストはLuna maxへ委譲。主担当が実装をレビューし、nullable最終入場・時刻範囲・不可日のperiod禁止を修正依頼。修正後の11テストを主担当でも確認した。モデル回答と原資料の判断、採用保留、統合は主担当が担当。

## 次の進め方

低価格モデルを使うなら、まず **文章・HTML・テキスト抽出可能なPDFで、開放日時が明示された未対応施設** に対象を絞る。灰色グリッドや色の凡例を読み取る施設を増やすには、汎用の表構造抽出を前段に置き、Lunaには抽出済み行と条件文の解釈を担当させる方式を別の固定資料で検証する。施設ごとの細かいプロンプト調整は継続しない。

今回の発見を使った改修後に同じ188件だけで採用を決めず、新しい施設・別月資料を保留テストとして追加する。Astraは候補正解の作成と差分確認に使い、実際に可と公開する経路は原資料との照合を残す。
